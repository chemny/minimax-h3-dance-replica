# 灰阶深度与时序检查

## 深度流程与参数边界

当前后端采用DA3计算深度、DA3Render转为灰阶；DA3Render不是H3插件，也与原声音频无关。模型、处理分辨率和渲染设置见 [presets.md](presets.md)，是当前实现的工作预设，不是所有视频必须使用的最优方案。

- 保持原片速度及连续帧顺序，按当前后端要求规范帧率/尺寸；补帧只在末尾，不在中间制造动作延迟。
- 保留模型返回的有效深度/sky信息；不混入原片RGB纹理，不默认叠加对数/CDF或时间平均。
- 不将灰阶清楚等同控制准确，也不把人物偏亮就判成只有黑白。DA3没有预测出的几何不能靠调对比度创造。
- 原生渲染器无显式种子输入时，不宣称灰阶像素逐次完全一致；记录实际节点参数，实验时复用输入条件。
- 预览整段肩臂遮挡、人物大小、转身、头发轮廓及时间轴。强度和控制区间的变化属于实验参数，不自动推广为通用修复。

历史对照及具体数值另见 [evidence.md](evidence.md) 的案例记录。可选自定义增强只在已授权实验中使用，不能作为渲染后的必经步骤。

## 默认：原生API深度阶段

按 [runtime.md](runtime.md) 配置任务并运行：

```bash
python3 "$SKILL/scripts/dance.py" depth --config "$CONFIG" --execute
```

`dance.py`仅上传规范片的交付帧，原生图为 LoadVideo/GetVideoComponents → LoadDA3Model → DA3Inference → DA3Render → CreateVideo/SaveVideo。图和prompt_id保存在任务目录`depth`，下载结果后仅在客户端末尾复制最后一张深度帧补齐内部网格，输出`depth/depth.mp4`和验证记录。不需要SSH、额外服务或服务器脚本。

检查分辨率、24fps、内部帧数、全片灰阶及完整解码后，才送入生成。`approve --item depth`记录Agent已核对的文件摘要；不自动判定动作准确。

## 可选：已有服务器Python执行方式

保留`scripts/depth_remote.py`供已有服务器执行环境使用，不是默认接入要求。配置必须显式提供`comfy_root`、`shared_root`、`source`（共享input内文件名）、`dest`、`frames`、`padded`、`width`、`height`；`comfy_url`可覆盖本机8188，`extra_model_configs`为本机附加模型配置。`ffmpeg`可显式指定，否则从PATH发现；不读取作者机器的runtime.json。该辅助脚本仅适用于已有私网无认证ComfyUI；有认证时优先使用统一API入口。

`renderer`默认为`da3render`，默认`render_seed=0`；自定义试验可选`custom_cdf`。统一API入口目前只实现用户选择的DA3Render分支，不能把辅助脚本的可选增强参数误传给原生节点。服务器脚本仍需用户已有执行权限，不自动创建SSH或安装环境。

## 转身慢的诊断顺序

1. 原片、24fps规范片、深度与结果按同一PTS/帧索引查看；区分角度不够、起转晚、回正晚和固定整体延迟。
2. 检查深度生成是否连续读帧，补帧是否仅发生在末尾；核对ControlNet未误接RGB。
3. 查当前图实际采样sigma和控制生效区间；控制百分比不是视频时长比例，也不能简单按步数取整。相关数值属于后端/任务参数。
4. 深度经VAE时空压缩，以模型残差软约束生成，不是每个视频帧的硬锁。提示词秒数也不是控制接口。
5. 输入已对齐时，可定位偏差发生在生成阶段；“只控制前两步导致延迟”仍是需要单变量试验的解释，不可单凭相关性断言。

没有证据时，不把增加强度、延长控制或提高灰阶对比度写成已知修复；用单变量对照验证，失败组合留在各自案例记录。
