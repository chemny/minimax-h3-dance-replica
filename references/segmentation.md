# 自动分段与共享边界

这是用户确认的长片工作规则，不是声称分段能自动消除人物漂移。默认目标约10秒；超过目标自动均衡分段，任何实际生成段不得超过15秒。可在任务配置设置 `segmentation.target_seconds`（4～15）和 `max_seconds`（不超过15），默认10/15；不把15秒当作所有硬件都能跑通的保证。需要手动坚持单段时显式 `enabled:false`，仍受后端单段上限约束。

## 图片生成前先算清单

1. 读取完整源片实际视频时长，以24fps统一源时间轴，保留原速度与原音乐。
2. 计算均衡段数、全局边界帧、每段时长、内部帧数需求、首尾图片映射及总图片数。避免最后留下不足2秒的短尾段；共享端点计入实际单段时长，内部17k+5补齐另行记录且只在末尾补帧。
3. N段只需要N＋1张唯一边界图。默认30秒约分为3段、生成4张图；14秒约分成2段、生成3张图。10秒/15秒为可配置目标及硬上限，按实际帧数计算，不凭口算固定数量。
4. 从原片对应边界取帧，统一人物/服装，用Codex编辑每张边界一次。第i段尾图与第i＋1段首图引用**同一个文件**，不得分别生两张“相似图”。全部边界图检查合格之后才能开始视频生成。
5. 切点是计算边界，不代表动作暂停。快速转身、遮挡和切镜处需核对边界可用性；不合适时先重新规划并记录，再制作图片，不边生成边临时改切点。当前脚本等长均衡，不具备自动理解动作或智能避开切点的能力。

## 生成与拼接

- 提示词先分析完整源片，再按每段全局起点裁出本地时间轴，保留跨段动作的进入/离开状态，不重启动作、不复用上一案例时间点。
- 每段使用自己的连续深度与对应共享首尾图，顺序提交，独立保存任务ID以便恢复，不并行争抢显存。
- 相邻段在源时间轴共享一帧；拼接去掉后一段的第一张重复帧。检查拼接后总帧数，没有丢失中间内容，不改速、不默认淡化或插帧隐藏跳变。
- 各段先输出无音乐画面，完成拼接后统一恢复原片音乐并核对音频包。不能分段反复编码音乐或因独立裁音频造成节奏断裂。
- 每个接缝检查前后连续帧的人物、服装、手势、运动方向、速度、背景和光照；共用边界图仅保证输入一致，不保证运动速度/加速度连续。
- 长片超出单段上限时不能静默只生成前15秒。显存不足须报告实际限制；调整尺寸或运行实现须说明，不能把分段规则当成显存绝对保证。

## 统一入口

```bash
python3 "$SKILL/scripts/dance.py" plan --config "$CONFIG"
python3 "$SKILL/scripts/dance.py" prepare --config "$CONFIG"
python3 "$SKILL/scripts/dance.py" anchors --config "$CONFIG"
```

`plan`只计算清单，写入任务目录`segmentation.json`，不取帧、不调用GPU。`prepare`规范整片并切段，输出`boundaries/source-*.png`和每段配置及接触表。`anchors`生成唯一边界图片请求，不调用生图接口。共享输出放到`boundaries/anchor-*.png`。

配置中的`performance`指完整源片表演记录。`compile`按计划裁成各段本地秒数；Agent仍需核对动作衔接。`approve --item anchors`要求全部边界图已齐；`depth --execute`逐段提深度，Agent检查每段后`approve --item depth`。`render --execute`逐段生成；`finish`去重拼接并一次恢复整片音轨；`compare`制作整片同步对照。`run --execute`按这些阶段推进，在缺素材或视觉核对时暂停。

已有单段任务仍按原图恢复，不自动拆分已有工作；要改为分段应新建任务目录。默认自动分段不适配任意封装API：沿用技能原生ComfyUI客户端，其他API须先验证等价能力。

实现状态：分段计算、共享文件映射、局部提示词时间、帧去重与整片音乐恢复须通过本机素材验证；真实多段GPU生成及接缝自然度另行验收，不以本机验证替代。
